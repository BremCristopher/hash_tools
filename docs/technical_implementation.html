1PDF SubFilter

首先检查 PDF 签名字典中的 /SubFilter 字段

"sm2-sm3"           → SM3withSM2
"adbe.pkcs7.sha256" → SHA256withRSA
"adbe.pkcs7.detached" → 需进一步检测

2PKCS#7 OID 解析

解析 SignerInfo 中的签名算法 OID

1.2.156.10197.1.501    → SM3withSM2
1.2.840.113549.1.1.11 → SHA256withRSA
1.2.840.113549.1.1.5  → SHA1withRSA

3Hash 长度推断

当 OID 解析失败时，从 messageDigest 长度推断

40 chars (20 bytes) → SHA-1
64 chars (32 bytes) → SHA-256/SM3
128 chars (64 bytes) → SHA-512

BER 编码自动降级

⚠️ 兼容性挑战：Apple Developer 等证书使用 BER 编码（允许不定长度），标准 cms crate 只支持 DER。

Hash Tools 的解决方案：

fn extract_message_digest(&self) -> Result<String, String> {
    // 1. 尝试 DER 解析 (快速路径)
    match self.extract_message_digest_der() {
        Ok(digest) => return Ok(digest),
        Err(e) if e.contains("indefinite length") => {
            // 2. 自动降级到 BER 二进制搜索
            return self.extract_message_digest_ber();
        }
        Err(e) => return Err(e),
    }
}

🔐 SM3withSM2 验证技术细节

📌 关键区分：messageDigest 验证与签名验证使用不同的哈希计算方式
验证阶段 计算公式 输入数据 目的
Hash 验证 SM3(M) M = ByteRange 内容 验证文档未被篡改
签名验证 SM2_Verify(e, sig) e = SM3(Z || SignedAttrs) 验证签名者身份

SM2 Z 值计算

// Z = SM3(ENTL || ID || a || b || xG || yG || xA || yA)
// 其中:
//   ENTL = ID 的比特长度 (2 bytes)
//   ID = 用户标识 (默认 "1234567812345678")
//   a, b = 椭圆曲线参数
//   (xG, yG) = 基点 G 坐标
//   (xA, yA) = 公钥点 P 坐标

fn calculate_sm2_z_value(pubkey: &Point) -> [u8; 32] {
    let ctx = SigCtx::new();
    ctx.hash("1234567812345678", pubkey)
}
